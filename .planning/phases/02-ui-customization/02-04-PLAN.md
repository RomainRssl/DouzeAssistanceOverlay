Key pitfall from RESEARCH.md:
- In VR mode, WPF Left/Top are NOT what positions the overlay in the headset.
  VR position is handled by IVRService.RegisterOverlay reading from OverlaySettings.
  The VR fields inform the VR service. After a drag in VR mode, update VrPosX/VrPosY
  AND call _vrService.UpdateOverlayTransform (or equivalent) if such method exists.
  Check OverlayManager.cs for how VR window positions are submitted to the VR service.

Anti-pattern: Do NOT call OverlayManager.ReinitializeOverlays() for VR profile switch —
this closes/reopens all windows. Use PropertyChanged instead (OverlaySettings.PosX triggers
BaseOverlayWindow to move its WPF Left/Top via OnSettingsChanged).

CRITICAL — Profile isolation invariant:
ApplyVrProfile MUST NOT write to Settings.PosX, Settings.PosY, Settings.OverlayWidth,
or Settings.OverlayHeight. These are the 2D fields and must remain intact so that
Apply2dProfile can restore the 2D layout from them without needing a separate backup.
Instead, set WPF window position directly on the overlay window object.
Apply2dProfile reads the still-intact 2D Settings fields and applies them directly to the window.

    --- VrProfileHelper.cs: New static helper ---

    ```csharp
    using LMUOverlay.Models; // check actual namespace
    namespace LMUOverlay.Helpers
    {
        public static class VrProfileHelper
        {
            /// <summary>
            /// If VR fields are not yet initialized, copies current 2D layout as starting point.
            /// Safe to call every time VR activates — only copies when null.
            /// </summary>
            public static void InitVrFromTwoD(OverlaySettings s)
            {
                if (s.VrPosX == null)
                {
                    s.VrPosX   = s.PosX;
                    s.VrPosY   = s.PosY;
                    s.VrWidth  = s.OverlayWidth;
                    s.VrHeight = s.OverlayHeight;
                }
            }

            /// <summary>
            /// Saves a drag result to the correct profile (VR or 2D).
            /// Call from BaseOverlayWindow.OnMouseUp passing IsVRModeActive.
            /// </summary>
            public static void SaveDragResult(OverlaySettings s, double newLeft, double newTop, bool isVrActive)
            {
                if (isVrActive)
                {
                    s.VrPosX = newLeft;
                    s.VrPosY = newTop;
                }
                else
                {
                    s.PosX = newLeft;
                    s.PosY = newTop;
                }
            }

            /// <summary>
            /// Saves a resize result to the correct profile (VR or 2D).
            /// Call from wherever OverlayWidth/OverlayHeight are saved on resize end.
            /// </summary>
            public static void SaveResizeResult(OverlaySettings s, double newWidth, double newHeight, bool isVrActive)
            {
                if (isVrActive)
                {
                    s.VrWidth  = newWidth;
                    s.VrHeight = newHeight;
                }
                else
                {
                    s.OverlayWidth  = newWidth;
                    s.OverlayHeight = newHeight;
                }
            }
        }
    }
    ```

    --- OverlayManager.cs changes ---

    4. ADD ApplyVrProfile and Apply2dProfile methods.

    CRITICAL DESIGN: ApplyVrProfile MUST NOT write to Settings.PosX, Settings.PosY,
    Settings.OverlayWidth, or Settings.OverlayHeight. Those 2D fields are the source of truth
    for Apply2dProfile. Writing VR values into them would corrupt the 2D layout — when VR mode
    ends and Apply2dProfile runs, it would read the now-overwritten values and "restore" the wrong
    positions. Instead, set WPF window Left/Top/Width/Height directly on the overlay window object.

    ```csharp
    /// <summary>
    /// Initializes VR fields from 2D layout (if not yet set) and repositions
    /// WPF windows to the VR positions BY SETTING WINDOW PROPERTIES DIRECTLY.
    /// Does NOT touch Settings.PosX/PosY/OverlayWidth/OverlayHeight so that
    /// Apply2dProfile can restore the 2D layout from those intact fields.
    /// </summary>
    public void ApplyVrProfile()
    {
        foreach (var o in _overlays.Values)
        {
            VrProfileHelper.InitVrFromTwoD(o.Settings);
            // Set WPF window position/size directly — do NOT write to Settings 2D fields
            if (o.Settings.VrPosX.HasValue) o.Left   = o.Settings.VrPosX.Value;
            if (o.Settings.VrPosY.HasValue) o.Top    = o.Settings.VrPosY.Value;
            if (o.Settings.VrWidth.HasValue  && o.Settings.VrWidth.Value  > 30) o.Width  = o.Settings.VrWidth.Value;
            if (o.Settings.VrHeight.HasValue && o.Settings.VrHeight.Value > 30) o.Height = o.Settings.VrHeight.Value;
        }
    }

    /// <summary>
    /// Restores overlays to their 2D layout after VR mode ends.
    /// Reads Settings.PosX/PosY/OverlayWidth/OverlayHeight, which were preserved intact
    /// because ApplyVrProfile never wrote to them.
    /// </summary>
    public void Apply2dProfile()
    {
        foreach (var o in _overlays.Values)
        {
            // 2D fields were never touched during VR mode — read them directly
            o.Left   = o.Settings.PosX;
            o.Top    = o.Settings.PosY;
            if (o.Settings.OverlayWidth  > 30) o.Width  = o.Settings.OverlayWidth;
            if (o.Settings.OverlayHeight > 30) o.Height = o.Settings.OverlayHeight;
        }
    }
    ```

    NOTE: The overlay window object accessed as `o` in _overlays.Values must be the WPF Window
    instance (BaseOverlayWindow). Confirm the type of _overlays values — if they are wrapped
    in a container, unwrap to get the actual Window before setting Left/Top/Width/Height.

    IMPORTANT: Check how ApplyVrProfile interacts with the existing VR service.
    In StartVR, the VR service registers overlays via RegisterOverlay — that call
    likely reads initial position from Settings. If the VR positions (VrPosX/VrPosY) differ
    from the current PosX/PosY, the VR service may have already submitted the wrong initial
    position. To fix: call VrProfileHelper.InitVrFromTwoD before RegisterOverlay in StartVR,
    then pass VrPosX/VrPosY to RegisterOverlay if it accepts a position parameter.
    Read the existing StartVR implementation to understand what parameters RegisterOverlay takes.
