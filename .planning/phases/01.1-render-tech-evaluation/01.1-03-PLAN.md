## WPF — Current Architecture

**Strengths:**
- No new dependencies
- Handles drag, resize, themes, 2D/VR profiles natively (BaseOverlayWindow already implements all Phase 2 requirements)
- Zero deployment risk

**Weaknesses:**
- RenderTargetBitmap is software-only (CPU) — confirmed open issue dotnet/wpf#9021
- Canvas children mutation every frame (ProximityRadar pattern) creates retained-mode overhead

**Phase 2 verdict:** WPF is SUFFICIENT for UI-01, UI-02, UI-03, UI-04. No render change required.

## SkiaSharp 3.119.2 (SKElement — raster backend)

**Strengths:**
- Imperative drawing eliminates WPF retained-mode overhead
- Lower GC pressure: fixed WriteableBitmap buffer vs per-frame visual tree mutations
- Enables future path: Skia bitmap → existing D3D11 UpdateSubresource upload

**Weaknesses:**
- NOT GPU-accelerated: SKElement uses software/raster rendering via WriteableBitmap
- D3D12 link-time dependency (see Deployment Risk below)
- Full overlay reimplementation required (high migration cost)

**Phase 2 verdict:** NOT required for Phase 2. Relevant for future VR-02 only.

## Deployment Risk: D3D12 Link-Time Dependency

SkiaSharp 3.119.x ships libSkiaSharp.dll with a link-time dependency on d3d12.dll. On Windows 10 pre-Creators Update (1703), application crashes on startup (~0.1% of installs). Minimum requirement if adopting SkiaSharp: Windows 10 1703+.

## Recommendation

### Phase 2 (UI-01 through UI-04): PROCEED IN WPF
